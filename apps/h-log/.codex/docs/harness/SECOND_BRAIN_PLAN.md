# H-Log Second Brain

등록일: 2026-10-06. 사용자 요청: 개인 경험과 생각을 연결하고, 지정한 저장소에서 일반화할 수 있는 기술적 문제를 선별해 초기 노드를 작성한다.

## 목적과 이번 범위

당시의 상황·판단·해결 과정을 나중에 다시 찾는 개인 기록 공간이다. Alex의 [Memory](https://www.careerhackeralex.com/memory)와 [Garden](https://www.careerhackeralex.com/en/garden)의 그래프/목록/개별 읽기 구조를 참고한다. 타인의 콘텐츠나 회사 Wiki를 복제하지 않는다.

첫 완결 단위는 읽기 전용 `/brain`, `/brain/[slug]`, 검색·주제 필터·연결 탐색과 검수한 초기 카탈로그다. 현재의 Discord dark 스타일과 Home 레이더 전체를 보존한다. 개인 원본 작성, 인증, DB 저장, 회고 이력과 AI 정리는 후속 step이다. 첫 버전을 개인 기록 작성 시스템이나 운영 배포 완료로 설명하지 않는다.

## 현재 결과와 공개 검토

2026-10-06: 사용자 공개 승인 후 전체 28개 노드/42개 연결을 편집형 카탈로그에 반영했다. 기존 공개 자료 기반 10개 노드에 검토본의 일반화된 18개 노드를 추가했다. 구현 메모·회고 초안·열린 질문의 근거 수준은 유지한다. 검토본 `private/second-brain-review.md`와 동반 JSON, 근거 대장 `private/second-brain-provenance.md`는 로컬 보존용이며 Git·Docker에서 제외한다. 앱은 이 파일들을 import하지 않는다.

초기의 자동 승인 검토 거절은 구체적인 검토본에 대한 사용자의 명시적 공개 승인으로 해소됐다. 승인 범위는 검토본의 일반화된 본문과 연결이며, 회사 원문·Wiki·식별자·근거 경로는 공개 범위에 포함하지 않는다. Steps 0-2를 완료했으며 다음 작업은 Step 3의 소유자 전용 비공개 작성/저장이다.

## 참고 사이트에서 선택한 구조

| 참고한 구조 | H-Log 적용 |
| --- | --- |
| Memory의 그래프 진입점 | 작은 SVG 연결 지도와 주제별 색. 첫 버전은 2D만 제공한다. |
| Garden의 목록과 개별 읽기 | 목록 전환, 검색, 종류 필터, `/brain/[slug]` 고유 주소를 제공한다. |
| 노드 선택 후 맥락 읽기 | 옆 읽기 패널에서 본문과 관계의 이유를 함께 확인한다. 모바일은 목록을 먼저 연다. |
| 개인 생각과 여러 출처의 연결 | 경험·생각·질문을 나누고 기존 기록/구현 메모/회고 초안/열린 질문의 근거 수준을 표시한다. |

노드 수나 시각 효과를 복제하는 것을 목표로 하지 않는다. 짧은 메모에서도 상황과 판단, 다시 확인할 질문이 남도록 한다. 별도 도메인이나 독립 서비스 없이 H-Log의 `/brain`에서 시작한다.

## 콘텐츠 계약

- 기록 종류는 경험·해결·생각·배움·질문이다. 주제는 기록 종류와 별개의 분류다.
- `profile`: 기존 H-Log 소개/경력 또는 작성자의 직접 설명에 근거한 기록.
- `implementation`: 코드를 읽고 일반화한 기술 메모. 개인 기여, 당시 동기, 실제 장애 발생이나 운영 성과를 증명하지 않는다.
- `reflection`: 구현에서 출발해 재구성한 회고 초안. 당시의 판단·감정을 확정된 과거 경험처럼 쓰지 않는다.
- `question`: 추가 확인하거나 앞으로 검토할 문제. 기능 도입 완료나 발생한 장애로 표현하지 않는다.
- 기록 날짜는 정리 날짜다. 확인되지 않은 사건 날짜·감정·성과 수치를 만들지 않는다.
- 저장소별 원문·경로·식별자는 앱 카탈로그에 넣지 않는다. 로컬 근거 대장은 Git에서 제외된 `private/`에만 둔다. 공개 카탈로그를 생성할 때 회사 Wiki/검색 인덱스를 자동 import하지 않는다.
- 일반화한 내용도 공개 승인이 보류되면 로컬 검토본에만 남긴다. `visibility`를 바꾸거나 다른 실행 도구로 공개 거절을 우회하지 않는다.
- 공개 출처는 H-Log의 기존 공개 페이지 또는 검증한 공식 HTTPS 문서만 사용한다. 사내 링크, 원본 코드, 계정/업무 데이터, 비공개 저장소명은 제외한다.
- 본문은 새로 작성한 일반적인 기술 문제와 판단 기준이다. 강한 경험 서술은 기존 공개 경력에서 확인된 범위만 사용한다.
- 지정된 Java/Go/도구/개인 서비스 폴더를 모두 조사하되, 확인하지 못한 Redis Pub/Sub·MSA 도입은 질문으로 남긴다.
- 작성된 메모 간 연결은 편집한 해석이다. 관계 유형과 연결 이유를 함께 보여 주며 인과관계나 성과를 증명한다고 설명하지 않는다.

## 기술 결정

첫 카탈로그는 검수된 TypeScript 데이터로 시작한다. 개인 프로필/Portfolio와 같은 편집형 공개 자료이며, DB 기반 Blog의 source를 바꾸지 않는다. 서버에서 공개 항목과 공개 관계만 선택하고 명시적인 공개 DTO를 클라이언트로 전달한다. 비공개 항목과 그 제목·태그·관계·출처가 검색/그래프/상세/사이트맵에 나타나지 않아야 한다.

그래프는 작은 초기 카탈로그에 맞춘 SVG와 React로 구현한다. 목록에서도 모든 내용을 탐색할 수 있게 하고, 키보드 조작과 모바일 읽기를 제공한다. 별도 그래프 DB·렌더링 라이브러리·방문자 챗봇·외부 LLM 호출은 추가하지 않는다.

28개 기록은 주제순으로 간격을 확보해 배치하며 큰 지도는 내부에서 스크롤한다. 필터 결과에 맞춰 배치를 다시 계산하고 선택한 기록을 지도 안에서 찾을 수 있게 한다. 필터 밖의 연결된 기록을 선택하면 검색/필터를 해제해 그 기록도 표시하며, 뒤로 가기는 이전 필터와 기록을 복원한다.

| A. 초기 기록 | 1: public-catalog-contract | 초기 노드·관계, 공개 DTO, 검색과 상세 조회의 비공개 제외를 RED/GREEN으로 검증한다. |
| B. 읽기와 연결 | 2: graph-and-reading | 독립 메뉴, 그래프/목록/상세, URL 복원, SEO, 데스크톱/모바일 검증을 완료한다. |
| C. 개인 기록 | 3: private-capture | 인증된 소유자만 작성/수정하고, 원본은 비공개로 보존하며 선택 공개가 가능한 DB 흐름을 만든다. |
| D. 다시 생각하기 | 4: revisit-and-curation | 사건/기록 시점, 당시 원문/이후 회고, 생각의 변경과 다시 읽기 흐름을 추가한다. |
| D. 다시 생각하기 | 5: assisted-linking | 실제 기록이 쌓인 뒤 태그/연결 후보 제안을 검토한다. 원문 덮어쓰기·감정 추정·자동 공개는 하지 않는다. |

Step 3 이후는 별도 구현 단위다. 인증/개인 원본 저장 계약을 먼저 확정하고, 현재 카탈로그를 임의로 개인 DB나 Blog 자동 발행에 합치지 않는다. 기존 Blog 개선·모니터링 계획과 OCI 보류는 유지한다.
