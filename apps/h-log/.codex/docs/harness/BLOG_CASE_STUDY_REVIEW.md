# H-Log 최근 글 사례 검수

검수일: 2026-10-21. [Phase 5 Step 2](../../../phases/editorial-trust-and-series/step2.md)의 **최근 글 조회가 늦어져도 홈은 먼저 보여주기** 초안을 검토했다. Step 2의 원고 준비·근거 검수는 완료했으며 실제 발행은 하지 않았다.

2026-10-15 문체 교정본을 이어서 수정했다. 새 글로 편수를 늘리지 않았고 기존 원본·사실 검토본·교정본과 자료 확인 시각을 보존했다. 이번 사실 보완본·최종 교정본·claim 대장·실행 결과는 Git/Docker 제외 경로 `private/case-study-review-2026-10-21/`에 있다. 이 문서는 공개 가능한 검수 요약이다.

## 글의 질문과 선택 이유

질문은 최근 글을 기다리는 동안 홈 소개도 기다려야 하는가다. 기존 글의 대기·빈 결과·오류 구분에 다음 내용을 보완했다.

- [ADR-032](ADR.md)에 기록된 이유: 기존 공개 글 조회 기준을 재사용하고, 조회 대기와 오류 처리를 최근 글 컴포넌트로 한정한다.
- 대안: 홈 함수가 조회를 마친 뒤 반환하는 방식, 브라우저가 별도 API로 조회하는 방식, 현재의 별도 서버 컴포넌트 방식을 비교했다. **이번 코드 검토에서 정리한 분석**이며 세 방식을 당시 구현·벤치마크한 경험으로 쓰지 않았다.
- 비용: 화면에 세 개를 표시해도 현재 loader는 공개 글 전체를 읽고 모델을 만든다. `pageSize`는 SQL 조회량 제한이 아니다. 별도 요약 조회는 실제 규모에서 병목을 확인한 뒤 검토한다는 기존 결정에 연결했다.
- 날짜: 기존 목록은 발행일 누락 시 갱신일을 사용한다. 실제 발행일이나 검증일을 확인했다는 뜻으로 설명하지 않는다.
- 재시도와 로그: native GET은 홈 전체를 다시 요청한다. 고정 오류 식별자만 남긴다는 설명은 해당 컴포넌트의 catch 범위로 한정했다.

H-Log의 공개 구현과 React 공식 문서만 사용했다. 회사 문서·내부 URL·접속 정보·연락처·근거 없는 성과 수치는 원고에 포함하지 않았다. 기본 privacy scanner와 수동 검토를 함께 했으며 운영 환경의 조직명 목록을 읽거나 운영 검수를 완료한 것으로 표시하지 않았다.

## 사실 보완 뒤 문체 교정

사실 보완본을 먼저 저장한 다음 `espada:humanize-korean`으로 산문 3곳을 다듬었다. 명사를 길게 이어 쓴 선택 이유와 반복적인 안내 문장을 짧게 바꿨다. 사실 보완본과 최종 교정본의 제목·표·코드·inline code·URL·날짜·숫자를 비교해 동일함을 확인했고, 사실·범위·불확실성은 수동으로 대조했다.

기존 초안에서 달라진 사실 설명은 대안의 검토 시점, 날짜 fallback, 전체 조회/모델 처리, 재시도·로그의 범위, 이번 테스트와 과거 검증의 구분이다. 이 보완을 문체만 고친 결과로 표시하지 않는다.

## 이번 검증

앱 디렉터리에서 실행했다.

```bash
node --no-warnings --test --experimental-strip-types lib/blog-public.test.ts
node --no-warnings --experimental-strip-types private/case-study-review-2026-10-21/verify.mjs
node private/case-study-review-2026-10-21/verify-docs.mjs
git diff --check
```

- 공개 글 테스트: **44/44 통과**, 실패·skip 없음.
- 원고 검수: claim 11개와 출처 연결, 근거 파일 11개의 hash, 이전 초안/manifest 보존, 문체 교정의 보호 항목 동일성을 확인했다. 기본 privacy 검사와 Markdown/HTML/hash 생성·공개 읽기 모델 파싱을 통과했다.
- 공개 경계: 메모리에 둔 `drafted` 원고의 공개 selector 결과는 0건이다. 본문 구조는 메모리의 파서 입력으로만 확인했으며 DB·repository·발행 callback은 호출하지 않았다.
- 문서/phase: Markdown·추가/변경된 상대 링크 37개·전체 phase JSON 42개와 상태·완료 개수·다음 단계 정합성, `git diff --check`를 통과했다. 원고와 문서만 바꿨으므로 lint·typecheck·build·DB integration·브라우저 검수는 이번 결과에 포함하지 않는다.
- 검수 스크립트의 비공개 함수 import와 제목 수 가정을 기존 공개 API·실제 원고에 맞춘 뒤 재실행했다. 앱 코드는 변경하지 않았다.

React 자료는 실제 재확인한 시각을 새 검수 대장에 기록했다. 2026-10-15 대장의 `sourceReviewedAt`은 바꾸지 않았다. 자동 발행 입력을 만들지 않았으며, 향후 수집·발행할 때도 기존 freshness/claim/privacy 검사를 다시 통과해야 한다.

## 사례 검수 당시 다음 단계

공개 경험 개선은 **16/19개 step 완료, 1개 blocked, 2개 pending**이다. Step 2 완료 후 [Step 1](../../../phases/editorial-trust-and-series/step1.md)로 돌아가 [시리즈 구성안](BLOG_SERIES_READINESS.md)의 나머지 두 원고를 준비한다. 시리즈 UI는 관련 원고 3편이 준비된 뒤 구현하며, 다음 작업을 시작하기 위해 이 첫 글을 운영에 미리 발행할 필요는 없다.

발행 전에는 최종 slug와 프로젝트 연결을 함께 맞춰야 한다. 기존 후보 `home-recent-posts-reading-boundary`와 로컬 연결용 `home-recent-posts`의 차이는 유지해 기록했고 공개 URL을 확정하거나 바꾸지 않았다. 새 원고의 실제 화면 검수·운영 발행·배포도 별도로 남아 있다.
